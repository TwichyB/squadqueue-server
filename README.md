# MosUP Server

เซิร์ฟเวอร์ + ฐานข้อมูลจริงสำหรับแอป MosUP (แอปหาเพื่อนเล่นเกม) เขียนด้วย Node.js, Express, PostgreSQL และ Socket.IO สำหรับแชทแบบเรียลไทม์ ใช้แทนเวอร์ชันเดโมที่เก็บข้อมูลในเบราว์เซอร์เท่านั้น — เวอร์ชันนี้มีบัญชีผู้ใช้จริง เข้าจากอุปกรณ์ไหนก็ได้ และข้อมูลไม่หายเมื่อล้างเบราว์เซอร์

โปรเจกต์นี้ผ่านการทดสอบจริงแล้ว: รันเซิร์ฟเวอร์กับ PostgreSQL จริง ทดสอบสมัคร/ล็อกอิน/บันทึกโปรไฟล์/ดึงรายชื่อผู้เล่น/แชทเรียลไทม์ผ่าน Socket.IO (รวมสถานะออนไลน์) ทั้งหมดทำงานถูกต้อง

## โครงสร้างโปรเจกต์

```
squadqueue-server/
├── public/            หน้าเว็บ (HTML/CSS/JS) ที่ผู้ใช้เห็น
├── src/
│   ├── routes/        API: auth, profile, candidates, chat
│   ├── middleware/     ตรวจสอบการล็อกอิน (JWT)
│   ├── db.js          การเชื่อมต่อฐานข้อมูล
│   ├── schema.sql     โครงสร้างตาราง
│   ├── migrate.js     สคริปต์สร้างตาราง
│   ├── socket.js      แชทเรียลไทม์ + สถานะออนไลน์
│   └── server.js      จุดเริ่มต้นเซิร์ฟเวอร์
├── .env.example       ตัวอย่างค่า config ที่ต้องตั้ง
├── render.yaml        ไฟล์ deploy อัตโนมัติสำหรับ Render
└── package.json
```

## รันบนเครื่องตัวเอง (ทดสอบก่อน deploy จริง)

ต้องมี Node.js เวอร์ชัน 18 ขึ้นไป และ PostgreSQL (ติดตั้งในเครื่อง หรือใช้บริการฟรีออนไลน์ก็ได้ เช่น Neon/Supabase)

1. ติดตั้งไลบรารี:
   ```
   npm install
   ```
2. คัดลอกไฟล์ตัวอย่าง config:
   ```
   cp .env.example .env
   ```
3. เปิดไฟล์ `.env` แล้วใส่ `DATABASE_URL` ของฐานข้อมูล Postgres ของคุณ และสร้าง `JWT_SECRET` ด้วยคำสั่ง:
   ```
   node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
   ```
   แล้วนำค่าที่ได้ไปวางใน `JWT_SECRET=`
4. สร้างตารางในฐานข้อมูล:
   ```
   npm run migrate
   ```
5. รันเซิร์ฟเวอร์:
   ```
   npm start
   ```
   แล้วเปิดเบราว์เซอร์ไปที่ `http://localhost:3000`

ปุ่ม "เข้าสู่ระบบด้วย Discord" จะยังใช้ไม่ได้จนกว่าจะตั้งค่า OAuth ตามขั้นตอนด้านล่าง (ถ้าไม่ตั้งค่า ปุ่มจะแจ้งเตือนเฉยๆ ไม่ error)

## Deploy ขึ้นใช้งานจริง

### วิธีที่แนะนำ: Render (มีไฟล์ blueprint ให้แล้ว)

1. อัปโหลดโค้ดโปรเจกต์นี้ขึ้น GitHub repository ของคุณ
2. เข้า [Render](https://render.com) → New → **Blueprint** → เลือก repo นี้
3. Render จะอ่านไฟล์ `render.yaml` แล้วสร้างให้อัตโนมัติ: เว็บเซอร์วิส + ฐานข้อมูล Postgres ฟรี พร้อมเชื่อม `DATABASE_URL` ให้เอง
4. หลังสร้างเสร็จ เข้าไปที่เว็บเซอร์วิส → แท็บ Environment → ใส่ค่า `JWT_SECRET` เอง (สร้างด้วยคำสั่งเดียวกับด้านบน)
5. รอ deploy เสร็จ ระบบจะรัน `npm install` และ `npm start` ให้อัตโนมัติ — **แต่ต้องรัน migration เองครั้งแรก**: ไปที่แท็บ Shell ของเว็บเซอร์วิสบน Render แล้วรัน `npm run migrate`
6. เข้าใช้งานได้ที่ URL ที่ Render ให้มา (เช่น `https://squadqueue-server.onrender.com`)

หมายเหตุ: แพลนฟรีของ Render จะพักเซิร์ฟเวอร์เมื่อไม่มีคนใช้งาน แล้วปลุกใหม่ตอนมีคนเข้า (ช้าประมาณ 30-60 วินาทีในครั้งแรก) ถ้าต้องการให้เร็วตลอดเวลาต้องอัปเกรดเป็นแพลนเสียเงิน

### ทางเลือกอื่น

- **Railway** (railway.app): สร้างโปรเจกต์ใหม่ → deploy จาก GitHub repo → เพิ่ม Postgres plugin → ตั้งค่า env vars เหมือนใน `.env.example` → รัน `npm run migrate` ผ่าน Railway shell
- **Vercel + ฐานข้อมูลแยก (Supabase/Neon)**: เหมาะกับ frontend แบบ static แต่ตัวเซิร์ฟเวอร์นี้เป็น Node/Express ที่ต้องมีการเชื่อมต่อ WebSocket (Socket.IO) ค้างไว้ตลอด ซึ่ง Vercel serverless ไม่รองรับดีนัก แนะนำให้ deploy ตัวเซิร์ฟเวอร์บน Render/Railway/Fly.io แทน แล้วใช้ Supabase หรือ Neon เป็นฐานข้อมูล Postgres ก็ได้ (แค่เปลี่ยนค่า `DATABASE_URL`)

## ตั้งค่ายืนยันอีเมล (Brevo API)

ตอนนี้การสมัครสมาชิกด้วยอีเมล/รหัสผ่านต้องกดยืนยันลิงก์ในอีเมลก่อนถึงจะเข้าสู่ระบบได้ (บัญชีที่ล็อกอินผ่าน Discord ไม่ต้องยืนยันซ้ำ เพราะผู้ให้บริการยืนยันอีเมลมาให้แล้ว)

โปรเจกต์นี้ส่งอีเมลผ่าน [Brevo](https://www.brevo.com) (HTTP API) แทนการต่อ SMTP ตรงๆ แบบ Gmail เพราะแพลนฟรีของ Render (และผู้ให้บริการฟรีอีกหลายเจ้า) บล็อกการเชื่อมต่อออกไปที่พอร์ต SMTP (25/465/587) ทั้งหมด ต่อให้ตั้งค่า Gmail ถูกทุกอย่างก็จะเจอ `ETIMEDOUT` เพราะเชื่อมต่อไม่ได้ตั้งแต่ต้น — Brevo ส่งผ่าน HTTPS ธรรมดาเลยไม่ติดปัญหานี้

ลองมาสองเจ้าก่อนหน้านี้แล้วไม่ผ่าน: Resend (แพลนฟรี) ส่งได้แค่หาอีเมลที่ใช้สมัคร Resend เองจนกว่าจะยืนยันโดเมน ส่วน SMTP2GO ไม่ให้สมัครบัญชีด้วยอีเมล gmail/yahoo เลยตั้งแต่ขั้นแรก (บังคับต้องมีอีเมลโดเมนส่วนตัว/บริษัท) — Brevo ไม่มีข้อจำกัดทั้งสองแบบนี้

1. สมัครบัญชีฟรีที่ https://www.brevo.com (ใช้อีเมลอะไรก็ได้ รวมถึง gmail)
2. ไปที่ Settings → Senders, Domains & Dedicated IPs
   - **ถ้ามีโดเมนของตัวเองแล้ว (แนะนำ — ส่งเข้า Gmail/Yahoo ได้แม่นกว่า)**: กด "Domains" → เพิ่มโดเมน → เอา DNS record (SPF/DKIM) ที่ Brevo ให้มาไปใส่ในหน้าจัดการ DNS ของโดเมน (เช่นที่ Porkbun/Namecheap) → รอยืนยัน แล้วจะส่งจากอีเมลอะไรก็ได้ที่ลงท้ายด้วยโดเมนนั้น เช่น `noreply@โดเมนคุณ.com`
   - **ถ้ายังไม่มีโดเมน**: กด "Senders" → "Add a Sender" → ใส่อีเมลของตัวเอง แล้วกดลิงก์ยืนยันที่ส่งเข้ากล่องจดหมาย (ใช้ได้เหมือนกัน แต่มีโอกาสตกสแปมสูงกว่าเล็กน้อยเพราะไม่มี SPF/DKIM ระดับโดเมน)
3. สร้าง API key ที่ Settings → SMTP & API → API Keys → Generate a new API key
4. นำค่าที่ได้ไปใส่ใน `.env` (หรือ Environment ของ Render):
   ```
   BREVO_API_KEY=xkeysib-xxxxxxxxxxxxxxxxxx
   BREVO_SENDER_EMAIL=noreply@โดเมนคุณ.com   (หรืออีเมลที่ยืนยันไว้ในข้อ 2)
   BREVO_SENDER_NAME=MosUP
   ```
5. ตั้งค่า `APP_BASE_URL` ให้ตรงกับโดเมนจริงที่ผู้ใช้เข้าเว็บ (เช่น `https://squadqueue-server.onrender.com`) — ค่านี้สำคัญมาก เพราะถูกใช้สร้างลิงก์ยืนยันในอีเมล ถ้าตั้งผิดหรือไม่ตั้งเลย ลิงก์อาจชี้ไปผิดโดเมน (โดยเฉพาะเมื่อรันหลัง proxy อย่าง Render) — สังเกตว่านี่คนละเรื่องกับโดเมนที่ใช้ส่งอีเมลในข้อ 2 ไม่จำเป็นต้องเป็นโดเมนเดียวกัน ต่อให้เว็บยังรันอยู่ที่ `squadqueue-server.onrender.com` ก็ใช้โดเมนใหม่แค่สำหรับส่งอีเมลได้เลย
6. ถ้าไม่ตั้งค่า `BREVO_API_KEY`/`BREVO_SENDER_EMAIL` ไว้ (ปล่อยว่าง) เซิร์ฟเวอร์จะไม่ส่งอีเมลจริง แต่จะพิมพ์ลิงก์ยืนยันออกทาง console log แทน — สะดวกสำหรับทดสอบในเครื่อง แต่ผู้ใช้จริงจะเข้าระบบไม่ได้ถ้าไม่มีใครส่งลิงก์ให้

แพลนฟรีของ Brevo ส่งได้ 300 อีเมล/วัน ซึ่งเกินพอสำหรับแอปขนาดนี้

## ตั้งค่า Login ด้วย Discord (จริง ไม่ใช่จำลอง)

1. ไปที่ https://discord.com/developers/applications → New Application
2. เข้าแท็บ **OAuth2** → คัดลอก **Client ID** และ **Client Secret**
3. ในหัวข้อ Redirects ให้เพิ่ม URL: `https://โดเมนของคุณ/api/auth/discord/callback` (ตอนทดสอบในเครื่องใช้ `http://localhost:3000/api/auth/discord/callback`)
4. นำค่าที่ได้ไปใส่ใน `.env` (หรือ Environment ของ Render):
   ```
   DISCORD_CLIENT_ID=...
   DISCORD_CLIENT_SECRET=...
   DISCORD_REDIRECT_URI=https://โดเมนของคุณ/api/auth/discord/callback
   ```
5. รีสตาร์ทเซิร์ฟเวอร์ ปุ่ม "เข้าสู่ระบบด้วย Discord" จะพาไปหน้ายืนยันตัวตนของ Discord จริง

## ลืมรหัสผ่าน

หน้าเข้าสู่ระบบมีลิงก์ "ลืมรหัสผ่าน?" ให้แล้ว ทำงานคล้ายระบบยืนยันอีเมล: กรอกอีเมล → เซิร์ฟเวอร์สร้างโทเคนสุ่มอายุ 1 ชั่วโมง → ส่งอีเมลผ่าน Brevo ตัวเดียวกับที่ตั้งไว้ด้านบน (ไม่ต้องตั้งค่าเพิ่ม) → ผู้ใช้กดลิงก์ในอีเมล → กรอกรหัสผ่านใหม่ → เข้าสู่ระบบให้อัตโนมัติ

จุดที่ตั้งใจทำไว้:
- endpoint `/api/auth/forgot-password` ตอบข้อความเดียวกันเป๊ะไม่ว่าอีเมลนั้นจะมีอยู่ในระบบหรือไม่ (กันไม่ให้ใครเอาไปเช็คว่าอีเมลไหนสมัครไว้บ้าง) — ถ้าไม่ได้ตั้งค่า Brevo ไว้ ลิงก์รีเซ็ตจะถูกพิมพ์ออก console log แทนเหมือนอีเมลยืนยัน
- โทเคนใช้ได้ครั้งเดียว หมดอายุใน 1 ชั่วโมง และผูกกับบัญชีที่ล็อกอินด้วยอีเมล/รหัสผ่านเท่านั้น (บัญชีที่ล็อกอินด้วย Discord ไม่มีรหัสผ่านให้รีเซ็ต)
- รีเซ็ตรหัสผ่านสำเร็จ = ถือว่ายืนยันอีเมลไปด้วยในตัว (พิสูจน์แล้วว่าเข้าอีเมลนั้นได้จริง)

## บล็อกผู้ใช้ / เลิกบล็อก

ในหน้าต่างแชท มีปุ่ม 🚫 ให้กดบล็อกอีกฝ่ายได้ทันที

- การบล็อกเป็นแบบ **สองทาง**: ไม่ว่าใครเป็นคนกดบล็อก ทั้งสองฝ่ายจะมองไม่เห็นกันในล็อบบี้อีกต่อไป และส่งข้อความหากันไม่ได้เลย (เช็คทั้งฝั่ง REST API และฝั่ง Socket.IO ตอนส่งข้อความจริง)
- กดปุ่มบล็อกแล้วแชทจะปิดทันทีและอีกฝ่ายจะหายไปจากล็อบบี้ของคุณ
- กดปุ่ม "ผู้ใช้ที่บล็อก" ที่แถบด้านบนเพื่อดูรายชื่อทุกคนที่คุณเคยบล็อกไว้ และกด "เลิกบล็อก" เพื่อยกเลิกได้ทุกเมื่อ (มีแค่คนที่กดบล็อกเท่านั้นที่ยกเลิกได้ อีกฝ่ายเลิกบล็อกให้ไม่ได้)
- ประวัติแชทเก่ากับคนที่ถูกบล็อกจะไม่แสดงจนกว่าจะเลิกบล็อก

## ปิดแจ้งเตือนเฉพาะคน (Mute) และเปิด/ปิดการแจ้งเตือนทั้งหมด

- ปุ่มกระดิ่งที่แถบด้านบนใช้เปิด/ปิดการแจ้งเตือนทั้งหมดได้จริงแล้ว (ทั้งการ์ดแจ้งเตือนในแอปและการแจ้งเตือนเดสก์ท็อป) ต่างจากเดิมที่กดได้ทางเดียว — สถานะนี้เก็บไว้ที่เบราว์เซอร์ของแต่ละคน (localStorage) แยกจากสิทธิ์ที่เบราว์เซอร์ขอไว้ ซึ่งเป็นเหตุผลที่ต้องทำแบบนี้: สิทธิ์ notification ของเบราว์เซอร์ (`Notification.permission`) ไม่สามารถถูกถอนออกด้วยโค้ดฝั่งเว็บได้เลยหลังจากอนุญาตแล้ว
- ในหน้าต่างแชทแต่ละคน มีปุ่ม 🔕 ให้ปิดแจ้งเตือนเฉพาะคนนั้นคนเดียว (mute) โดยไม่ต้องปิดแจ้งเตือนทั้งหมด — คนที่ถูก mute ยังคุยด้วยได้ปกติ แค่จะไม่มีการแจ้งเตือนเวลาส่งข้อความมาหรือตอนจับคู่กันใหม่
- การ mute เป็นการตั้งค่าเฉพาะเบราว์เซอร์ (เก็บใน localStorage ต่อผู้ใช้ที่ล็อกอิน) ไม่ใช่การตั้งค่าฝั่งเซิร์ฟเวอร์ ถ้าเปลี่ยนเบราว์เซอร์หรือเครื่อง จะต้อง mute ใหม่

## แนวเกม (genres)

- นอกจาก "เกมที่เล่นประจำ" มีช่อง **"แนวเกมที่ชอบ"** แยกต่างหาก (เลือกได้สูงสุด 8 จากทั้งหมด 14 แนว) เช่น Survival, Cozy, Farming, Sandbox/Building, RPG, FPS/Shooter, MOBA ฯลฯ — ใช้เป็นอีกมิติหนึ่งในการคำนวณ % ตรงกัน ควบคู่กับเกม/วัน/เวลา/สไตล์เดิม (สัดส่วนน้ำหนักคะแนน: เกม 35%, แนวเกม 15%, เวลา 20%, วัน 15%, สไตล์ 15%)
- แก้ไขได้จากหน้า "แก้ไขโปรไฟล์" เหมือนฟิลด์อื่นๆ

## เพศ และ สนใจเพศไหน

- ตัวเลือก "เพศ" ของตัวเองมี 4 แบบ: ชาย, หญิง, Non-binary, และขอไม่เปิดเผย
- ถ้าเลือกเป้าหมาย **"เป็นมากกว่าเพื่อนก็ได้ถ้าถูกใจ"** ในหน้าแก้ไขโปรไฟล์ จะมีช่องเพิ่มขึ้นมาให้เลือก **"สนใจเพศไหน"** (ชาย/หญิง เลือกได้มากกว่า 1) โผล่ขึ้นมาเฉพาะตอนนั้น ถ้าเลือกเป้าหมายอื่นอย่างเดียว (หาเพื่อนเล่นเกมอย่างเดียว) ช่องนี้จะซ่อนไปและไม่ถูกบันทึก
- ถ้าใครตั้งค่านี้ไว้ คนอื่นจะเห็นเป็นแท็บ "สนใจ: ชาย/หญิง" ต่อจากแท็บเป้าหมายในการ์ดของเขา

## ระดับ % match ขั้นต่ำที่อยากได้ (ตัวกรองด่วนในล็อบบี้)

- มีแถบเลื่อน (slider) **"% ขั้นต่ำ"** อยู่ที่แถบตัวกรองด้านบนของล็อบบี้เลย (ไม่ต้องเข้าไปตั้งในหน้าแก้ไขโปรไฟล์ให้รก) ปรับขึ้น/ลงได้ทีละ 10% ตั้งแต่ 0% ("ไม่กำหนด") ไปจนถึง 100% เหมือนแถบเลื่อนปรับเสียง — ลากด้วยเมาส์หรือกดปุ่มลูกศรซ้าย/ขวาตอนโฟกัสที่แถบก็ได้
- ถ้าตั้งไว้ เช่น 70% แล้วเจอคนที่ % ตรงกับคุณต่ำกว่านั้นในล็อบบี้ จะมีสัญลักษณ์ ⚠️ ขึ้นข้างชื่อเขาเตือนไว้ แต่**ยังกดทักไปคุยได้ตามปกติ** ไม่ได้ถูกซ่อนหรือบล็อกแต่อย่างใด เป็นแค่ตัวช่วยให้กรองด้วยสายตาเร็วขึ้นเท่านั้น
- ค่านี้บันทึกไว้ในโปรไฟล์ (sync ข้ามอุปกรณ์ได้เหมือนฟิลด์อื่น) ไม่ใช่แค่เก็บในเบราว์เซอร์เดียว

## จุดที่ตรงกัน / ไม่ตรงกัน ในแต่ละการ์ด

- ในการ์ดแต่ละคนที่ล็อบบี้ แต่ละหมวด (เกม/วัน/เวลา/สไตล์/แนวเกม) จะมีบรรทัดสีเขียวบอกว่า **"ตรงกัน: ..."** โชว์เฉพาะสิ่งที่ตรงกันจริง (เช่นเล่นเกมเดียวกัน) — บรรทัดสีเขียวนี้โชว์ตลอดเวลา ไม่ถูกซ่อน
- ถ้ามีจุดที่ไม่ตรงกันด้วย จะมีอีกบรรทัดสีเทาบอกว่า **"ไม่ตรงกัน: ..."** ต่อท้าย — อันนี้ซ่อน/แสดงได้ด้วยปุ่ม **"ซ่อน/แสดงจุดที่ไม่ตรงกัน"** ที่แถบตัวกรองด้านบนของล็อบบี้ บางคนอยากเห็นรายละเอียดนี้ บางคนไม่อยากเห็น (อยากดูแค่ % รวมกับจุดที่ตรงกันพอ) กดปุ่มนี้ซ่อน/แสดงได้ทันที (แถบเปอร์เซ็นต์และตัวเลขยังอยู่เหมือนเดิมเสมอ) — ค่านี้จำไว้เฉพาะเบราว์เซอร์ของแต่ละคน (localStorage) เหมือนกับ mute
- **เกมที่พิมพ์เองผ่านช่อง "เพิ่มเกมอื่น..."** จะเทียบว่าตรงกันไหมแบบไม่สนตัวพิมพ์เล็ก/ใหญ่และช่องว่างหัวท้าย (เช่น "Dota 2" กับ "dota 2" หรือ "dota 2 " ถือว่าเป็นเกมเดียวกัน) กันปัญหาที่บางคนมีเกมตรงกันจริงแต่ % และบรรทัด "ตรงกัน" ไม่ขึ้นเพราะพิมพ์ต่างเคสกัน

## ลำดับการเรียงคนในล็อบบี้ + ปักหมุด

- ค่าเริ่มต้นจะเรียงคนที่ % ตรงกันเยอะไว้บนสุดเสมอ แต่ก่อนจะถึงเกณฑ์นั้นมี 2 อย่างที่ถูกดันขึ้นไปอยู่บนกว่า:
  1. **คนที่ปักหมุดไว้** — กดปุ่ม 📌 มุมขวาบนของการ์ดใครก็ได้เพื่อปักหมุดให้อยู่บนสุดเสมอ ไม่ว่า % จะตรงแค่ไหน กดซ้ำเพื่อเลิกปักหมุด (จำไว้เฉพาะเบราว์เซอร์ของแต่ละคน เหมือนปุ่ม mute)
  2. **คนที่เคยคุยด้วยกันมาก่อน** — ถ้าเคยส่งข้อความหากันแล้ว (ไม่ว่าใครทักก่อน) จะถูกจัดไว้เหนือคนที่ยังไม่เคยคุยกัน แม้ % จะต่ำกว่าก็ตาม
  3. หลังจากนั้นถึงเรียงตาม **% ตรงกัน** จากมากไปน้อยตามปกติ
- ลำดับความสำคัญโดยรวม: **ปักหมุด > เคยคุยด้วยกัน > % ตรงกัน** (ถ้าเลือกโหมดเรียง "ออนไลน์ก่อน" ในดรอปดาวน์ ออนไลน์จะถูกแทรกเข้ามาเป็นเกณฑ์ก่อน % แต่ยังอยู่หลังปักหมุดและเคยคุยด้วยกันเสมอ)

## แท็บ "แชทล่าสุด" (คนที่เคยคุยด้วยแล้ว)

- มีแท็บสีส้มแปะอยู่ริมจอด้านซ้ายเขียนว่า "💬 แชท" — โผล่มาเองเมื่อเริ่มมีบทสนทนากับใครสักคนแล้ว (ถ้ายังไม่เคยคุยกับใครเลยแท็บนี้จะไม่โชว์)
- กดแท็บแล้วจะมีแผงเลื่อนออกมาจากด้านซ้าย แสดงรายชื่อทุกคนที่เคยคุยด้วย เรียงจากคุยล่าสุดไปเก่าสุด แต่ละแถวโชว์แค่ชื่อกับข้อความล่าสุดที่คุยกัน (ถ้าเราเป็นคนพิมพ์เอง จะขึ้น "คุณ: ..." นำหน้า)
- กดที่รายชื่อไหนก็เปิดหน้าต่างแชทกับคนนั้นได้ทันที
- รายการนี้อัปเดตสดๆ ทันทีที่มีข้อความใหม่เข้ามาหรือส่งออกไป (ผ่าน socket) ไม่ต้องรีเฟรชหน้า

## ตั้งชื่อเล่นให้เพื่อนที่คุยด้วย (เห็นเฉพาะคุณ)

- ในหัวข้อหน้าต่างแชท ข้างชื่อของอีกฝ่ายจะมีไอคอนดินสอ ✏️ ให้กดเพื่อตั้งชื่อเล่นให้คนนั้นได้ (สูงสุด 24 ตัวอักษร)
- กด **Enter** เพื่อบันทึก, กด **Esc** เพื่อยกเลิกโดยไม่บันทึก, หรือคลิกที่อื่น (blur) ก็บันทึกให้อัตโนมัติเหมือนกด Enter
- ถ้าลบข้อความในช่องจนว่างแล้วกดบันทึก จะกลับไปแสดงชื่อจริงของเขาเหมือนเดิม
- ชื่อเล่นนี้จะแสดงแทนชื่อจริงทุกที่ที่คุณเห็นคนนั้น: การ์ดในล็อบบี้, หัวข้อหน้าต่างแชท, แท็บ "แชทล่าสุด", การแจ้งเตือนข้อความใหม่/จับคู่ใหม่, และรายชื่อผู้ใช้ที่บล็อก
- **สำคัญ: ชื่อเล่นนี้เก็บไว้ในเบราว์เซอร์ของคุณเท่านั้น (localStorage) ไม่ถูกส่งขึ้นเซิร์ฟเวอร์เลย** เพราะฉะนั้นมีแค่คุณคนเดียวที่เห็น อีกฝ่ายจะไม่รู้เรื่องด้วยว่าคุณตั้งชื่อเล่นให้เขาว่าอะไร และถ้าเปลี่ยนเบราว์เซอร์หรือเครื่อง จะต้องตั้งใหม่ (เหมือนกับปุ่ม mute และปักหมุด)
- อวาตาร์ (ตัวอักษรย่อ + สี) ยังคงอิงจากชื่อจริงเสมอ ไม่เปลี่ยนตามชื่อเล่น

## อิโมจิในแชท

- ในหน้าต่างแชท มีปุ่ม 🙂 ข้างช่องพิมพ์ข้อความ กดแล้วจะเด้งแผงเลือกอิโมจิขึ้นมา เลือกอันไหนก็จะแทรกเข้าไปในข้อความที่กำลังพิมพ์อยู่ทันที ไม่ต้องพึ่งอิโมจิคีย์บอร์ดของเครื่อง

## เวลาที่ส่งข้อความ

- ทุกข้อความในแชทจะมีเวลาที่ส่ง (ชั่วโมง:นาที) ต่อท้ายข้อความเสมอ ทั้งข้อความเก่าที่โหลดย้อนหลังและข้อความใหม่ที่เพิ่งพิมพ์ส่ง

## ความปลอดภัยที่ทำไว้ให้แล้ว

- รหัสผ่านถูกเข้ารหัสด้วย bcrypt ก่อนบันทึกเสมอ ไม่มีการเก็บรหัสผ่านตรงๆ ในฐานข้อมูล
- เซสชันใช้ JWT เก็บใน cookie แบบ `httpOnly` (จาวาสคริปต์ฝั่งเว็บอ่านไม่ได้ ป้องกัน XSS ขโมย token) และตั้ง `secure` อัตโนมัติเมื่อรันบน production (บังคับส่งผ่าน HTTPS เท่านั้น)
- **ห้ามเผยแพร่ค่า `JWT_SECRET` และ Client Secret ต่างๆ ที่ไหนก็ตาม** — เก็บไว้ใน `.env` เท่านั้น (ไฟล์นี้ถูกใส่ไว้ใน `.gitignore` แล้วเพื่อไม่ให้หลุดขึ้น GitHub โดยไม่ตั้งใจ) และตั้งค่าแยกใน Environment ของแพลตฟอร์มที่ deploy จริง

## ข้อจำกัดที่ควรรู้

- สถานะ "ออนไลน์" เก็บไว้ในหน่วยความจำของเซิร์ฟเวอร์ ใช้ได้ดีถ้ารันเซิร์ฟเวอร์เครื่องเดียว (ซึ่งเพียงพอสำหรับแพลนฟรีของ Render/Railway) แต่ถ้าจะขยายเป็นหลายเครื่องพร้อมกันในอนาคต จะต้องเพิ่มระบบเก็บสถานะกลาง เช่น Redis
- รายชื่อผู้เล่นในล็อบบี้ (`/api/candidates`) ดึงมาสูงสุด 200 คนล่าสุดที่อัปเดตโปรไฟล์ ถ้าผู้ใช้เยอะมากในอนาคตอาจต้องเพิ่มการแบ่งหน้า (pagination)
